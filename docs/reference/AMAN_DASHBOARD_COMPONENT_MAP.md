# Aman Member Intelligence Dashboard — Component Map

This map records how the user-supplied dashboard artwork is divided into native Compose components. The image is a visual target, not a background asset; the screen remains scrollable at the phone's native viewport.

**Current reference (this pass): dark theme.** The user attached a dark-theme artwork (deep-navy shell, white data cards, green active pill) and asked for it to be implemented; it supersedes the earlier light-only visual rule for this screen. Page, header, member card and nav rail render navy (`MIColor.page`/`navy`/`pill`); section cards remain light so dense data stays readable.

## Screen order

| Region | Compose component | Data and behavior |
| --- | --- | --- |
| More (left), BAD GYM wordmark, MEMBER INTELLIGENCE, Search + Alerts (right) | `AppBrandStrip` in `ReferenceMemberIntelligenceDashboard.kt` | Dark circular `DarkHeaderAction` buttons; wordmark is green BAD + light GYM. Alert badge derives from `snapshot.issues.size` and is hidden at zero (the artwork shows "3"; honest zero wins). Search opens the roster picker, Alerts shows the selected member's issues, More opens scope/about copy. |
| Time-based greeting, portrait, crown/status, name/meta, plan chips, elapsed ring, joined/goal/branch | `MemberSummaryCard.kt` → `SummaryAvatar`, `PlanChip`, `ActiveChip`/`InactiveChip`, `StatusRing`, `FooterItem` | Navy gradient card with a teal corner glow and "Good Morning/Afternoon/Evening 👋" derived from the device clock. Ring: green elapsed arc on a dark track with days-remaining center; avatar ring green while active (gold otherwise), crown badge marks verification. Footer is Joined / Goal / Branch only — the plan validity range lives in the Payment & Plan header chip, so nothing is duplicated. Optional age, gender, goal, branch, and photo stay omitted/fallback when missing. |
| Overview, Payment, Attendance, Workout, Progress, Nutrition, Machine, More | `HorizontalMemberMenu` | Horizontally scrollable dark pills with icon + label; the active pill is green (Overview by default). Section destinations scroll the list; modules not implemented here show honest notices. More opens About. |
| **Body Stats** title, weight/muscle/body fat/BMI tiles, sparklines, goal note | `BodyProgressPanel`, `BodyMetricTile`, `MiniSparkline` | First section in the artwork order. Tile label sits at the bottom (`Weight (kg)` etc.); only recorded metrics render; deltas are since-joined baseline; goal-aware colors use the declared goal, BMI retains its band label. The artwork's header chevron is omitted — no body-detail flow exists, so it is not rendered dead (commented in source). |
| Payment & Plan title, plan capsule, paid/due summary, Next Due, receipt action | `PaymentPlanPanel` + `PlanRangeChip` | Compact block matching the artwork: paid/due state from outstanding balance with a green-check state tile; **Next Due leads with the due date** plus a relative-days chip (the amount due, when any, is the headline of the left block); receipt button is a real action. Capsule shows the plan range and is descriptive, not a fake plan-switch button (its artwork chevron is omitted for that reason). |
| "View Detailed Analytics →" button + dialog | Analytics item in the LazyColumn → `AnalyticsDialog` | Hosts what the compact Payment block no longer shows: **12-month `PaymentHistoryChart`** (aggregated by calendar month, timing colors only when known, upgrade month gets a gold marker, "No transaction" is not called a missed payment), plus derived summaries — lifetime paid/outstanding, attendance counts (only categories that exist), workout avg/peak/lowest/MoM, body deltas since join. |
| Ring + status counts + weekday calendar, `‹ Month ›` nav | `AttendancePanel`, `MonthNav`, `AttendanceDayCell`, `CompactAttendanceCount`, `CircularKpi` | Layout follows the artwork: ring left, counts middle, calendar right. Month navigation is real and bounded join-month → current-month; arrows disable at the bounds (no dead clicks). The current month uses the server visits/target ring; an earlier month derives only from its records and renders "No records for …" with an em-dash ring when none exist (never 0%). Present/absent/late/holiday/unknown/no-record stay visually distinct. |
| Full-width workout chart, `‹ Month ›` nav, Avg/Peak/Lowest tiles, legend | `WorkoutPanel`, `MonthNav`, `WorkoutMonthChart`, `WorkoutStatTile` | All values derive from dated workouts for the browsed month. Recorded durations are bars; confirmed no-workout is red; unknown is gray and never drawn as 0 (legend + note kept). Stat tiles show Avg / Day, Peak and Lowest with their dates; a month without records shows an honest empty line. The artwork has no MoM stat — it moved to the analytics dialog, where it appears only when both months are comparable. |
| Search, notification, receipt, About, Analytics dialogs + snackbar | Dashboard dialog composables and `MemberIntelligenceScreen` host | Light Material dialogs on the dark shell. Search changes member data, receipt displays actual fixture transactions, notices disclose destinations not connected in this build. |

## Reference values and fixture boundary

`MemberScenarios.compactSummaryAman()` is a **stub-only visual fixture**, reached by BG305 and selected as the initial demo member for this reference. Its workout ledger derives 48m average, 52m peak (Oct 10), 12m low (Oct 16), and +12% vs September. Body measurements derive 69.5kg, 57.2kg, 17.6%, and BMI 22.8, with deltas since the joined baseline. Attendance covers the current month only and workouts cover current + previous month, so month browsing exercises both real data and honest empty states. `AmanReferenceScenarioTest` locks the derivations. It does not populate or change production repository records.

The source art has a tall-device vs reference-canvas aspect mismatch. The app uses native dp/sp sizes and scrolls; screenshots are not stretched to claim pixel equality. Device proof and current limits are recorded in `docs/PIXEL_PERFECT_ACCEPTANCE.md`.
